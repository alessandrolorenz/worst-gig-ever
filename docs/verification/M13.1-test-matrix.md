# M13.1 Test Matrix

## Countdown

| Case | Expected |
|---|---|
| Start from READY | enters COUNTDOWN |
| countdown beat 1 | shows `3`, pad pulses |
| countdown beat 2 | shows `2`, pad pulses |
| countdown beat 3 | shows `1`, pad pulses |
| countdown beat 4 | shows `GO`, pad pulses |
| before GO | no Defense spawn |
| before GO | no Groove scoring |
| before GO | no Groove miss |
| before GO | no Integrity change |
| before GO | vocalist timeline frozen |
| GO boundary | transitions to active gameplay exactly once |
| GO beat | not scored |
| one beat after GO | first scored Groove beat |
| old M10 count-in | not stacked after countdown |

## Input / Geometry

| Case | Expected |
|---|---|
| tap center of new pad | eligible Groove tap |
| tap just outside configured pad | not Groove |
| target overlaps pad | one valid tap may resolve Groove + target once each |
| two fingers | remain distinct |
| nested art beneath touch | coordinate mapping remains surface-relative |
| pulse visual layer | does not become touch target |

## Difficulty Freeze

The following values must be byte/logically unchanged unless formatting/refactor only:

- BPM
- PERFECT window
- GOOD window
- target spawn cadence
- target speeds / fastball timing
- hitbox forgiveness
- Integrity
- vocalist timeline
- round duration
- Defense score values
- Groove score values

## Lifecycle

| Case | Expected |
|---|---|
| background during countdown | countdown cancelled, return READY |
| return from background | no stale countdown progression |
| pause during PLAYING | existing pause behavior |
| restart after complete | countdown starts fresh |
| restart after ruined | countdown starts fresh |

## Determinism

Equivalent elapsed-time schedules at different tick sizes must produce the same:

- countdown step sequence;
- GO transition time;
- first scored Groove beat;
- Groove judgements;
- target schedule after gameplay start.
