# M14.1 — Touch Feedback and Render Cost

## Trigger and scope

The owner tested the M14 EAS APK on the Galaxy S23 FE, approved the visuals,
and reported sluggish bottle/mug taps. They authorized investigation and fixes.
Do not treat the previously passing browser smoke as physical performance proof.

Preserve approved artwork, canonical asset dimensions, composition, all three
ambient poses, Groove timing, hit regions, scoring, spawn schedules and engines.
No new dependency, remote build, commit, or publication is implied by this fix.

## Evidence before implementation

- The 33 PNGs shrank from 18.14MiB to 9.25MiB compressed. Canonical dimensions
  did not increase; their total decoded RGBA area remains 71.06MiB. Bottle is
  256x512, mug384x384. Resolution alone does not explain the regression.
- Every engine frame re-renders all performer/crowd image stacks despite poses
  changing only a few times per second. Mutable domain objects require scalar
  snapshot props at memo boundaries; memoizing the objects would freeze state.
- GroovePad uses a 1920x1080 SVG for a 640x210 ellipse. Installed
  react-native-svg15.11.2 Android SvgView invalidation recycles its bitmap and
  drawOutput allocates a new ARGB bitmap at the native view size. This includes
  the large transparent area and device density, before parent canvas scaling.
- Targets and feedback change image layout dimensions/positions every frame.
- New hit effects are aged by the preceding frame's delta immediately after
  creation, shortening or removing feedback during a slow frame.
- The existing native processor emits start synchronously; the domain already
  judges touch-down, not release. No confirmed intentional tap-delay timer.

## Implementation contract

1. Restrict the pad SVG surface to its visual bounds plus stroke margin, with a
   viewBox preserving existing canvas coordinates. No change to pulse or hitbox.
2. Memoize static scenery and pose stacks with primitive changing inputs; keep
   all pose bitmaps resident to preserve the no-flicker behavior.
3. Animate moving image transforms instead of resizing/repositioning their
   layout boxes each tick. Preserve world centers, scales, rotation and depth.
4. Disable image fade-in explicitly for transient game feedback. This is a
   precaution, not a claimed cause: RN0.79 already disables fade for Android
   packaged resources; the 300ms default applies to other source types.
5. Advance existing presentation effects before creating new feedback, so a
   delayed frame cannot consume an effect before its first displayed frame.

## Verification and limits

Run all code/art gates; add geometry and slow-frame-feedback regression tests.
Compare render work using identical browser CPU-throttled scenarios and inspect
screenshots. Verify native launch where available. Report browser measurements
as browser results, not as Galaxy FPS. Final touch comfort and release-native
performance require the owner to retest a new APK. Do not lower art quality
without evidence that it is needed.
